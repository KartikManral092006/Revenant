For JavaScript and TypeScript developers

Replace a dead npm package, and see how closely the replacement behaves like the original.

Many projects still install packages that nobody maintains. They get no security fixes, and some have known vulnerabilities. Revenant records what a dead package actually does, builds a replacement from that record, then runs both on the same inputs and shows you the result.

See a full example: lodash.set → Browse the four packages

No login. Revenant reports evidence, not proof: a match score tells you how many tested inputs agreed, not that every input would.

Why this exists

If a dependency is dead, a developer has three options today. Each one has a catch.

Without Revenant

  • Keep it and live with unfixed security bugs.
  • Rewrite it by hand: slow, and easy to get subtly wrong.
  • Ask an AI to rewrite it, with nothing to show the new code behaves like the old.

With Revenant

  • The old package's behavior is recorded as evidence.
  • The evidence becomes a spec your AI coding tool can build from.
  • The rebuild is compared with the original on 1,000 inputs. Deliberate security fixes are listed, not hidden.

How it works: five steps

Each package page walks through these steps in order. Steps 1, 2, 3 and 5 run in your browser. Step 4 happens in Kiro, the AI coding tool used to do the rebuild.

  1. 1

    Autopsy

    Check the package's health: last release, known vulnerabilities, downloads.

    In your browser
  2. 2

    Run the original on 1,000 generated inputs and record what it does.

    In your browser
  3. 3

    Reverse Spec

    Turn that record into a written spec. Each requirement points to the recorded evidence behind it.

    In your browser
  4. 4

    Resurrection

    Rebuild the package from the spec. A hook re-runs the comparison on every save.

    In Kiro
  5. 5

    Rebirth Report

    Compare old and new on the same inputs: match score, security fixes, differences.

    In your browser

Who this is for

You will get the most from it if

  • You depend on a small utility package that nobody maintains.
  • You want a modern replacement you can read, not a black box.
  • You want to see what changed, and why, before you switch.

What you can do here

  • Read the health check of each package.
  • Download a Kiro spec bundle and rebuild it yourself.
  • Inspect the rebuild and its match score.

Questions

Does a high match score mean the rebuild is safe to use?

It is evidence, not proof. The score counts how many of the generated inputs gave the same result. Inputs that were not generated are not covered, so read the coverage figures next to it.

Can I try my own package?

Not on this site. It only runs the four packages above, inside an isolated sandbox. To use the method on your own package, download a spec bundle and follow the repository README.

Do I need an account?

No. Everything on this site works without logging in.

What does "dead" mean here?

No new release for more than two years, or the package is deprecated, or its repository is archived. Each package page shows which applies.
